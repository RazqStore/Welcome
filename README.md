# Razq Store — دليل الإعداد

موقع متجر Razq (ديسكورد + فايف ام): صفحة رئيسية واحدة، صفحة قوانين، سلة، تقييمات، ثيم فاتح/داكن، تسجيل بحساب ديسكورد أو جوجل، ولوحة تحكم منفصلة.

## محتويات المجلد

| الملف | وظيفته |
|---|---|
| `index.html` | الصفحة الرئيسية (المنتجات، التقييمات، السلة) |
| `rules.html` | صفحة القوانين (عدّل النصوص مباشرة داخل الملف) |
| `config.js` | إعدادات الموقع (مفاتيح Supabase، رابط الديسكورد) |
| `css/style.css`, `js/*.js` | التصميم والأكواد |
| `assets/` | الشعار (`logo.png`) وبنر المعاينة (`banner.png`) |
| `supabase/schema.sql` | قاعدة البيانات والصلاحيات |
| `admin/` | لوحة التحكم (ترفعها على دومين/ريبو ثاني) |

الخط المستخدم: **Tajawal**. العناوين والأزرار تستخدم ملفك `assets/fonts/Tajawal-Bold.ttf`، والنصوص العادية تستخدم Tajawal 400/500 من Google Fonts. لو تبي الموقع يشتغل بالخط حتى بدون إنترنت، حط ملفات `Tajawal-Regular.ttf` و`Tajawal-Medium.ttf` في `assets/fonts/` وأضف لهم `@font-face` في أول `css/style.css`.

## 1) إنشاء قاعدة البيانات (Supabase — مجاني)

1. ادخل https://supabase.com وأنشئ مشروعاً جديداً.
2. من **SQL Editor** الصق محتوى `supabase/schema.sql` كاملاً واضغط **Run**.
3. من **Project Settings → API** انسخ `Project URL` و `anon public key` وحطهم في:
   - `config.js`
   - `admin/config.js`

مفتاح `anon` مصمم يكون ظاهراً في الموقع. الحماية الفعلية تعتمد على سياسات RLS الموجودة في `schema.sql`، ولا تضع مفتاح `service_role` في أي ملف.

## 2) تفعيل الدخول بديسكورد

1. https://discord.com/developers/applications ← **New Application** ← تبويب **OAuth2**.
2. انسخ `Client ID` و `Client Secret`.
3. في Supabase: **Authentication → Providers → Discord** فعّله وألصق القيمتين.
4. انسخ **Callback URL** الظاهر في Supabase (يشبه `https://xxxx.supabase.co/auth/v1/callback`) وأضفه في Discord تحت **OAuth2 → Redirects**.

## 3) تفعيل الدخول بجوجل (اختياري — حالياً مخفي)
الموقع حالياً يعرض زر ديسكورد فقط. لو فعّلت جوجل لاحقاً، غيّر `AUTH_PROVIDERS` إلى `["discord", "google"]` في `config.js` و`admin/config.js`.


1. https://console.cloud.google.com ← أنشئ مشروعاً ← **APIs & Services → OAuth consent screen** (نوع External، وأدخل اسم التطبيق وإيميلك).
2. **Credentials → Create Credentials → OAuth client ID** (نوع Web application) وأضف نفس **Callback URL** من Supabase في Authorized redirect URIs.
3. انسخ `Client ID` و `Client Secret` إلى Supabase: **Authentication → Providers → Google**.

**هل يحتاج رخصة تجارية؟** لا. جوجل وديسكورد ما يطلبون رخصة. تحتاج فقط حساب مطوّر مجاني. وبما أن الموقع يطلب فقط الاسم والإيميل والصورة (صلاحيات أساسية)، ما تحتاج مراجعة/توثيق من جوجل. حط التطبيق على **In production** من شاشة الموافقة عشان يقدر أي شخص يدخل (في وضع Testing يدخل فقط الحسابات اللي تضيفها كمختبرين). يُفضّل وجود رابط سياسة خصوصية بسيط عند نشره للعموم.

## 4) روابط العودة بعد تسجيل الدخول

في Supabase: **Authentication → URL Configuration**
- **Site URL**: رابط موقعك الرئيسي.
- **Redirect URLs**: أضف رابط الموقع ورابط لوحة التحكم (مع `/**` في آخره).

## 5) الرفع على GitHub Pages

1. أنشئ ريبو (مثلاً `razq`) وارفع محتويات المجلد **ما عدا `admin/`**.
2. **Settings → Pages** ← Branch: `main` ← Save.
3. افتح `index.html` و `rules.html` وبدّل `YOUR-USER.github.io/razq` في وسوم `og:image` و `og:url` برابط موقعك الحقيقي. هذا اللي يخلي بنر الصورة وعبارة "حياكم الله نورتو" يطلعون عند إرسال الرابط في الديسكورد (يجب أن يكون رابط الصورة كاملاً).
4. إذا غيّرت المعاينة بعد ما أرسلت الرابط قبل، الديسكورد يخزّن النسخة القديمة فجرّب رابط جديد (مثل `?v=2`).

## 6) لوحة التحكم على دومين ثاني

- ارفع مجلد `admin/` في **ريبو منفصل** (مثلاً `razq-admin`) وفعّل له GitHub Pages، ثم اربطه بدومينك الثاني من **Settings → Pages → Custom domain**.
- أضف رابط اللوحة في Redirect URLs كما في الخطوة 4.
- **صلاحية الدخول:** إخفاء الرابط وحده لا يحمي اللوحة. اللي يحميها أن حسابك فقط موجود في جدول `admins`. أي شخص ثاني يفتح الرابط يشوف شاشة "لا يملك صلاحية" ولا يقدر يقرأ أو يعدّل شيء لأن قاعدة البيانات نفسها ترفض.

### جعل حسابك أدمن
1. افتح الموقع الرئيسي وسجّل دخولك مرة واحدة (بديسكورد أو جوجل).
2. من Supabase SQL Editor شغّل (بدّل الإيميل بإيميل الحساب الذي سجلت به):

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'YOUR_EMAIL@example.com';
```

> إذا سجلت بديسكورد وإيميل حسابك غير ظاهر، ابحث عن المستخدم في **Authentication → Users** وانسخ الـ UID، ثم:
> `insert into public.admins (user_id) values ('الـ UID هنا');`

بعدها ادخل لوحة التحكم بنفس الحساب.

## ماذا تقدر تسوي في اللوحة
الإحصائيات، إضافة/تعديل/حذف المنتجات (ظاهر/مخفي، شارة، سعر قبل الخصم، صورة)، الطلبات وتغيير حالتها، العملاء، المسجلين، التسويق (شريط إعلان + أكواد خصم)، حذف التقييمات، وتغيير رابط سيرفر الديسكورد.

## العملات
تدخل الأسعار في اللوحة **بالدينار الكويتي (KWD)**. الموقع يحدد دولة الزائر تلقائياً ويعرض الأسعار بعملته (ريال سعودي، درهم، دولار، يورو... إلخ)، وفي أعلى الموقع قائمة يغيّر منها الزائر العملة بنفسه ويتذكرها المتصفح. أسعار الصرف تتحدث تلقائياً كل 12 ساعة، والسلة تعرض أيضاً السعر الأساسي بالدينار. الطلب يُسجَّل دائماً بالدينار الكويتي.
إذا كنت شغّلت `schema.sql` قبل هذا التحديث، شغّل هذا مرة وحدة لدعم 3 خانات عشرية:
```sql
alter table public.products alter column price type numeric(10,3), alter column old_price type numeric(10,3);
alter table public.orders alter column total type numeric(10,3);
```

## طريقة الدفع
عند "إتمام الطلب" يُسجَّل الطلب برقم، وتظهر نافذة تقول للعميل **"روح الديسكورد وافتح تذكرة"** مع زر لرابط السيرفر. العميل لازم يكون مسجل دخول. لو أردت إضافة بوابة دفع لاحقاً أخبرني وأربطها.

## الإيميل (Gmail) — هل ينفع؟
- مع الدخول بديسكورد/جوجل **ما يُرسل أي إيميل**، فما تحتاج SMTP لتسجيل الدخول.
- إذا أردت إرسال إيميلات (مثل إشعار بكل طلب جديد أو رسائل التسجيل) ممكن تستخدم Gmail:
  1. فعّل **التحقق بخطوتين** في حسابك ثم أنشئ **App Password** من https://myaccount.google.com/apppasswords
  2. في Supabase: **Authentication → SMTP Settings** ← Host: `smtp.gmail.com` ، Port: `465` ، Username: إيميلك ، Password: الـ App Password.
  3. حدّ Gmail حوالي 500 رسالة يومياً، وهو مناسب لمتجر صغير.
- إشعار الطلبات بالإيميل يحتاج Supabase Edge Function صغيرة (أكتبها لك إذا طلبت).

## وضع المعاينة
إذا ما عبّيت `config.js` يشتغل الموقع بمنتجات تجريبية للمعاينة فقط، والتقييمات تُحفظ في متصفحك، وتسجيل الدخول معطّل.
